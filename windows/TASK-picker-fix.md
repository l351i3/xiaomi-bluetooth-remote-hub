## §0 根因与修复方式（30 秒读懂）

### 0A. 「试几下就出错弹窗」——Tk 解释器跨线程回收崩溃（本次关键修复）

- **根因**：旧实现（v1.1）每次按 PICK 都在**新线程**里创建、用完销毁一个独立的 Tk 解释器。
  Tk 要求「解释器只能在其创建线程里销毁」，而 Python GC 的回收时机不定 → 一旦解释器对象
  在非创建线程被回收（或解释器内部 async handler 在错误线程存活），Tk 直接
  `Tcl_AsyncDelete: async handler deleted by the wrong thread` → **fatal，进程弹错误框并 abort**。
  触发时机随 GC 不定 → 表现为「试几下才炸」。
- **修复**：**常驻 Tk 线程**。进程内只创建一次 root（withdraw 隐藏 + mainloop 常驻、100ms 泵），
  每次 PICK 只开关一个 Toplevel —— 解释器永不销毁，跨线程回收问题从根上不存在。
  另把 `root.report_callback_exception` 重写为**只记日志、绝不弹窗**（回调异常不再能触发报错框）。
- **附带**：崩溃曾把接收端进程带死 → 新更新脚本已支持「接收端未在运行」的冷部署（自动用
  计划任务/默认目录定位并重启，不再要求进程存活）。

### 0B. 「太难看，要图标」——图标网格 UI（对齐 Mac AppPicker）

- 6 列图标网格：每个应用 = **真实 exe 图标（64px 基准）+ 名称**；深色底 `#23272e`、
  选中项蓝色描边框、标题/提示行、固定尺寸无滚动条。
- 交互与 Mac 版 100% 对齐：初始选中第 2 项（≈上一个应用）、↑/← 上移、↓/→ 下移、
  **环绕移动**、OK 打开、返回/ESC 取消、**10 秒无操作自动取消**。
- 图标提取：`PrivateExtractIconsW`（按目标像素直出）→ 32bpp DIB → alpha 合成到底色
  （防透明像素出黑边）→ 缩放 → Tk PhotoImage；提取失败自动兜底
  `SHGetFileInfoW`，再失败显示空框（不阻塞选择器）。

### 0C. 高 DPI 适配（用户硬性要求）

- 全布局按系统 DPI 缩放：`scale = winfo_fpixels("1i")/96`（钳制 1.0~3.0），
  单元格 / 图标 / 间距 / 标题全部按比例 —— 125%/150%/200% 缩放下观感一致，
  图标**按目标像素提取**（放大不糊）。
- **多屏**：按「光标所在显示器的工作区」居中（GetCursorPos + MonitorFromPoint +
  GetMonitorInfoW，自动避开任务栏；失败回退主屏）。

### 0D. v2.1 三修复（上机实测反馈：图标大小不一 / 名称带后缀 / 设置图标不对）

- **0D-1 图标视觉尺寸归一（「图标大小不一」）**：
  根因 = 不同年代 exe 的图标画布留白不同（老式图标四周留白多、现代图标满幅），
  按同一画布缩放后**内容视觉大小不齐**。修复 = 图标管线在合成前加两步纯图
  处理：`trim_rgba`（按 alpha 通道求内容外接框裁掉空白，补 4% 透气边距；全透明/
  过小/本就满幅的保守原样）→ `square_pad_rgba`（非正方形透明补方、居中保比例）。
  效果：每个图标的**内容都撑满同一方框**，网格里视觉大小一致。
- **0D-2 应用名净化（「只要显示应用名字就好，不要带一堆文字后缀」）**：
  根因 = 旧版直接取窗口标题（如 `main.py - Visual Studio Code`、`xxx - 文件资源
  管理器`）。修复 = 新增 `app_display_name()`：读 **exe 版本资源**的
  `FileDescription`（version.dll：`GetFileVersionInfoSizeW` →
  `GetFileVersionInfoW` → `VerQueryValueW`，语言块**中文 0804 优先**），
  失败再退路 exe 主名去 `.exe`。按 exe_key 缓存，选择器只显示纯净应用名。
- **0D-3 UWP 真身图标（「设置明明有自己的图标，为什么用了个其他的图标」）**：
  根因 = UWP 应用（设置/计算器等）的窗口宿主进程是 `ApplicationFrameHost.exe`，
  旧版对该进程直接取图标 → 拿到**宿主壳的通用图标**。修复 = `is_host_process()`
  命中宿主时用 `host_child_pid()`（EnumChildWindows 枚举子窗口 → 取**可见子窗口
  的真实 PID**，如设置 = `SystemSettings.exe`）替换窗口归属，再按真身进程取
  **图标与名称**。效果：设置 = 齿轮、计算器 = 计算器图标。

### 0E. v2.2 三修复（二轮实测：「图标大小还是不一样」/「切换时图标框大小在变」）

- **0E-1 ★ 图标框/单元格尺寸恒定（「左右切换的时候图标框大小也在变」——根因）**：
  选择器 cell 的子件（图标/名称标签）用 **pack** 布局摆放，但固定尺寸调用的
  是 `cell.grid_propagate(False)` —— Tk 里 grid_propagate 只对 **grid 管理的子件**
  生效，对 pack 子件无效 → cell 的固定尺寸从未生效 → **cell 宽被应用名文本撑开**
  （Tk 实验实测：生产现状各 cell 请求宽 27 / 125 / 58 / 133px 不等，随名字长短变），
  选中蓝框跟着忽大忽小、窄格里的 64px 图标还会被横向裁切。
  修复 = 改为 `cell.pack_propagate(False)`（悬停实测：全部 cell 恒定 96×100）。
  附带两处布局加固：① `pick_layout` 面板宽公式补上每格 grid padx（旧公式漏算 →
  末列被裁 12px）；② 显示前 `update_idletasks` 后按实际请求尺寸兜底校正窗口
  （防字体/DPI 差异裁切）。
- **0E-2 光学尺寸归一 v2（「图标大小还是不一样」——v2.1 只做了一半）**：
  v2.1 的 trim + square_pad 只统一了「**画布**」——方形内容撑满画布，但圆形
  （同径圆面积 = 方形的 78.5%）、长条内容与方形内容的**视觉大小仍不齐**。
  v2.2 = 按「**内容有效面积**（alpha>8 的像素数）开根」把每个图标归一到同一视觉量级
  （目标 = `OPTICAL_REF × 图标px`，REF=0.84），直接置入正方形画布；配套**预乘
  双线性缩放**（缩放时以 alpha 加权平均颜色 → 透明像素的 RGB 不再污染边缘）。
  参数：放大上限 2.0×（防糊）、缩小下限 0.15×、内容大边 ≤96% 画布（钳制防溢出）。
- **0E-3 Windows 真机补丁正式合入（阻断级，防再退化）**：
  Windows 侧上机实测发现并回传三处修复（此前因全量分发被覆盖丢失过一次，
  本轮**正式合入上游 v1.5，成为唯一上游**）：① `apps_from_windows` 补写 `exe_key`
  键（原 `_icon_photo_for` 只读 `exe_key`，而产出是 `key` → 键恒空 → 图标全部退化
  为首字母占位，且无日志）；② 键名双重兼容（`exe_key` → `key` 回退）；
  ③ `PhotoImage` 改 `base64.b64decode(...).decode("latin1")` + `format="PPM"`
  传入（Tk 8.6 的 `-data` 不解码 base64，直接传会 `TclError: couldn't recognize
  image data`）。→ 防再回改：离线测试内置源码约定守护（见 actions_offline_test.py 第 13 节）。

### 0F. v2.3 三件（三轮反馈：「界面颜色不好看」/「长名显示不全」+ 防抖修复）

- **0F-1 配色重做（「界面颜色不好看」）**：底 `#23272e`（中灰蓝、发闷）→ **`#151a21`**
  （深炭冷调、更沉稳有层次）；选中填充 `#2b4a7e`（亮而浊）→ **`#1b2c48`**（哑光深蓝，
  与 `#3b82f6` 亮蓝描边同调，与遥控台 active 样式同族）；名称双色——非选中 `#d7dee9` /
  选中 `#ffffff`。**ICON_BG 同步 `(0x15,0x1a,0x21)`**（图标合成底色=窗口底，不出色差块）。
- **0F-2 长应用名滚动显示（「app 名称长的显示不全」）**：旧版 `name[:14]` 硬截断、
  且文本超宽被格边横向裁切（「Windows 资源管理器」显示成「ndows 资源管」）。新增两个纯逻辑：
  `fit_prefix`（非选中：像素预算内取最长前缀 + `…`）与 `cycle_slice`（选中：`name + 3 空格`
  环形序列的跑马灯窗口）；**选中项每 180ms 推进 1 字符循环滚动**，非选中项静态截断。
  名称预算 = 格宽 − 10×缩放（两侧留白）；像素度量走真字体 measure（中英混排精确，
  本机已用真字体集成冒烟验证宽度全程 ≤ 预算）。
- **0F-3 win_receiver 防抖首击语义修复（v1.6 配套）**：`handle_ext` 里
  `now - _ext_last.get(action, 0.0) < d` 把「从未触发（默认 0.0）」在**单调时钟从 0 起
  的环境**（刚开机 / 虚拟化 / 部分解释器）误判为「d 秒内刚触发」→ 扩展动作首击被吞。
  改 `None` 哨兵显式判定（`last is not None and now-last < d`）。本机以 3.9（monotonic=0.04）
  与 3.13（=16 万）双解释器对照实测；新增防回归测试（低时钟首击入队 / 同刻重复仍防抖）。

### 0G. v2.4 两件（四轮反馈：「两行时上下键也左右移动」/「计算器图标不对」）

- **0G-1 网格方向导航（「两行的时候，上下键也是左右移动，这不符合操作直觉」）**：
  根因 = 旧版 ↑/↓ 与 ←/→ 同为**线性 ±1 移动**（对齐 Mac AppPicker 旧语义；两行
  网格下按 ↑/↓ 在视觉上表现为左右横移）。修复 = 新增 `grid_move` 纯逻辑：
  **↑/↓ = 垂直移动**（相邻行同列优先；该列在末行不满时取最近列；首行 ↑ /
  末行 ↓ 回绕到另一端）；**←/→ = 行内水平**（行尾 → 下一行首、行首 → 上一行尾）。
  单行 / 单列时 ↑↓ 自动退化为线性（旧行为不变）；选择器按键分派改走 grid_move。
- **0G-2 UWP 真实图标·Shell 通路（「计算器图标不对，系统自带图标显示不对」）**：
  根因 = v2.1 只解决了「宿主壳通用图标」问题（取真身 exe 图标），但 **UWP 真身
  exe（如 WindowsApps 下的 Calculator.exe）的内嵌资源 ≠ 系统实际显示的图标**——
  显示图标由 shell 从应用清单（manifest / logo 资源）解析，与 exe 内嵌是两套资源。
  修复 = 新增 **Shell AppsFolder 通路**：取窗口 AUMID（`SHGetPropertyStoreForWindow`
  → `PKEY_AppUserModel_ID`；失败回退 `GetApplicationUserModelId(pid)`）→
  `shell:AppsFolder\<AUMID>` → `IShellItemImageFactory.GetImage`（ICONONLY|SCALEUP）
  → HBITMAP → RGBA → 复用既有后处理管线（裁白→补方→光学归一→合成→缩放）。
  UWP/包应用优先走此通路（触发 = ApplicationFrameHost 宿主 **或** 包应用路径
  〔WindowsApps / 沉浸式控制面板; 纯逻辑 `is_uwp_path`〕——覆盖全部系统自带应用），
  任一环节失败自动回退 exe 内嵌资源（设置齿轮等既有行为不回归）；
  COM 全走 ctypes 手写 vtable（不引入 comtypes 依赖）。

### 0H. v2.5 一件（五轮反馈：「颜色不太好看；改成跟 Mac 版一样，灰色」）

- **0H-1 配色对齐 Mac AppPicker（浅灰磨砂 HUD 风格）**：
  背景 = v2.3 配色以「遥控台同色系」为目标做成深炭蓝（`#151a21` 底 + `#1b2c48` 选中），
  与 Mac 实况不符——**Mac 版实测为浅灰磨砂玻璃（半透明 HUD 材质）**：面板呈中灰、
  文字近黑、选中项为**系统蓝描边 + 蓝灰填充**。修复 = 按 Mac 实拍截图**逐像素采样**
  反推色值并逐项落地：底 `#151a21` → **`#8a8a8a`**（磨砂灰实色近似——HUD 为半透明材质，
  取「深色背景下」的典型合成观感）；选中填充 `#1b2c48` → **`#6c84af`**（系统蓝 32%
  叠灰底的合成近似）；选中边框 `#3b82f6` → **`#017aff`**（macOS 系统蓝）；文字由浅色系
  （`#e8ecf1`/`#8b949e`/`#d7dee9`）改 **`#141414` 近黑**（对齐浅色模式 labelColor——
  提示行 / 占位字母 / 名称两态同色）。**`ICON_BG` 同步 `(0x8a,0x8a,0x8a)`**（图标合成
  底色=窗口底，透明图角与面板无缝）。本机已用同色值渲染冒烟截图核验（与 Mac 实拍并排比对一致）。

### 0I. v2.6 一件（六轮反馈：「图标外围有一圈灰色底色，没有完美融合进 UI」）

- **根因（Tk 无 alpha 通道 + 合成实底不匹配）**：Tk PhotoImage 不支持透明通道，图标必须
  先**预合成实底**（`composite_rgba_on_bg`）才能显示；旧版只生成了「非选中 = 窗口灰底
  `#8a8a8a`」**一套**。图标处于**选中格**（填充 `#6c84af`）时，图标方块的灰底在蓝底上
  外露成**一圈灰色**（v2.4 深色时代同缺陷已存在，但深灰叠深蓝不显眼——换浅色后被放大）。
  证据 = v2.4 实拍截图**像素扫描**：选中格横向剖面读出 `#1b2c48`(填充) → `#151a21`(tile
  灰底 22px) → 图标 → `#151a21` → `#1b2c48`。
- **修复（双底色变体）**：图标管线 `_finish_icon_ppm` / `_uwp_icon_ppm` / `_make_ppm_b64`
  增加 `bg` 参数；新增常量 **`ICON_BG_SEL = (0x6c, 0x84, 0xaf)`**（= SEL 填充同色）；
  `_icon_photo_for(..., sel=True)` 生成选中变体（缓存键加 bg 维度）；选择器构建时每个图标
  生成**两套** PhotoImage，`_paint` 在选中切换时换用对应变体 → 透明区域分别贴合灰底/蓝底，
  对齐 Mac（NSImage alpha 天然透过选中 32% 蓝填充）。
- **效果**：选中 / 非选中两种状态下，图标透明区均与格底**完全同色**（本机渲染核验图
  `picker-v26-fix-preview.png`：修复前灰块清晰可见 → 修复后无缝）。

## §2 验收（长按 home → 逐条做）

1. **版本确认**：`receiver.log` 应出现 `=== remotehub-win receiver v1.6 starting ===`（重启后）。
2. **图标网格（新样式）**：长按 home → 弹出选择器应为：**6 列图标网格**（每个应用一个
   真实图标 + 名称）、**浅灰磨砂底**、选中项有**蓝色描边框**、顶部标题、底部近黑提示
   （「↑↓←→ 选择 · OK 打开 · 返回 取消 · 10s 自动关」）。
   - **2a. 图标视觉大小一致（v2.2 光学归一）**：所有图标的**视觉大小应一致**——
     不只有方形图标，**圆形图标（如同径圆形应用的图标）、长条形内容也应在视觉上
     与方形图标同量级**（不再出现「有的图标大、有的图标小」，也不再有圆形显得
     偏小的情况；均为按内容有效面积归一）。
   - **2b. 纯应用名（v2.1）**：名称应只显示应用名（如 `Visual Studio Code`），
     **不带** `main.py - `、` - 文件资源管理器` 之类的窗口标题后缀。
   - **2c. 设置图标（v2.1）**：**设置**应显示自身**齿轮图标**（不再是宿主壳的
     通用窗口图标）。
   - **2g. ★ 计算器图标（v2.4）**：**计算器**应显示**系统实际的计算器图标**
     （由 shell 从应用清单解析的图标——与开始菜单/任务栏展示一致；不再是 exe
     内嵌的旧资源样式）。设置/照片/商店等其它系统应用同样校验。
   - **2d. ★ 图标框大小恒定（v2.2）**：**左右/上下切换选中项时，每个格子与选中
     蓝框的尺寸应保持恒定** —— 不应随应用名长短变化（例：「微信」与「Visual
     Studio Code」的格子应为同一尺寸；切换过程中蓝框不允许忽宽忽窄）。
   - **2e. ★ 配色对齐 Mac（v2.5）**：整面板为**浅灰磨砂风格**（中灰底、近黑文字，
     对齐 Mac AppPicker 实况）；选中项为**系统蓝描边（#017aff）+ 蓝灰填充（#6c84af）**；
     顶部提示行与全部应用名文字为**近黑色**。观感应与 Mac 版并排观感一致
     （可对照随附的 Mac 实拍与渲染核验截图）。
   - **2f. ★ 长名滚动（v2.3）**：**选中**名称超宽的应用时（如 `Windows 资源管理器`、
     `Google Chrome`），名称应**循环滚动显示全名**（每 ~0.18s 进 1 字符，滚完
     接分隔空格回到开头）；**非选中**的超宽名称应显示**截断 + `…`**（如
     `Windows 资源管…`），且**不再出现文字被格子边缘硬裁**（旧版「ndows 资源管」）。
     切换选中项时，滚动应从名称开头重新开始。
   - **2h. ★ 选中格图标融合（v2.6）**：**选中**格子里的图标，其**透明区域应与蓝灰选中
     填充完全融合**（图标周围**不再出现一圈灰色方块**；左右切换选中时，图标底色应随
     格底一起切换）。非选中格与灰底的融合为回归确认项。
3. **移动（v2.4 网格方向）**：**↑/↓ 在行间垂直移动**（两行以上时不再表现为左右
   横移）—— 同列上下、首行 ↑ 回绕末行、末行 ↓ 回绕首行；**←/→ 行内水平**
   （行尾 → 下一行首、行首 ← 上一行尾）；**单行时 ↑↓ 退化为线性**（旧行为不变）。
   按住方向键连发快移保持。
4. **OK 打开**：高亮停在某应用 → 遥控 **OK** → 该应用被切到前台、选择器关闭。
5. **取消 ×2**：① 遥控 **返回** → 关闭不切换；② 再开一次，**放着不动 10 秒** → 自动关闭。
6. **★ 反复捶打（本次关键修复点）**：连续「长按 home 打开 → 返回取消」**至少 6 次**，
   并中途用方向键快速乱按 —— **不应再出现任何报错弹窗**（旧版「试几下就炸」已根治）。
7. **DPI（有缩放的话）**：若本机显示缩放为 125%/150%（设置→系统→屏幕→缩放），窗口与
   图标应按比例放大、图标清晰不糊；改缩放（或拖到不同缩放率的第二显示器）后重开
   选择器，仍应正确。
8. **日志证据**：上述操作期间 `receiver.log` 应出现：

   ```
   picker tk thread ready (Tk v8.6)                 ← 仅在升级后第一次 PICK 时出现
   KEY UP DOWN -> picker (routed)                   ← 按键直连路由（v1.4 起）
   picker open: 12 apps, sel=1, dpi=150% (924x396)  ← 打开时一行：应用数/初始选中/DPI/窗口尺寸
   picker auto-cancel (10s 无操作)                   ← 自动取消时
   ```

   （`routed` = 直连路由生效；若看到 `-> vk=0x..` 说明新版本未生效。
   **禁止出现**：`picker tk callback error` 连续刷屏或任何错误弹窗。）
